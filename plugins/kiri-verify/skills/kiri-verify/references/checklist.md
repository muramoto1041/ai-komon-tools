# 検証チェックリスト

`kiri_scan.py` が機械的に拾えるのは下の「A. 書式」の一部だけ。B〜D は本文を読んで判断する。
各項目には、実際の業務システムでよく見つかる形を一般化した例を付けている。

## A. 書式（ヘルプとの照合）

- [ ] 条件付きの `手続き実行` / `分岐` で、`( 条件式 )` の後のカンマが抜けていないか。
  - 例：`手続き実行 (&初回 = 0) 初期化処理(&結果)` → 正しくは `手続き実行 (&初回 = 0), 初期化処理(&結果)`。
  - カンマが抜けていても今は動いている可能性がある。ヘルプの書式には反するので「直すべき箇所」に入れる。
- [ ] `検索` / `絞り込み` が `[項目]{ 比較式 }` または `[項目]_&変数` の形になっているか。
  - `検索 [コード]=&値`、`絞り込み [日付] <= &基準日, [日付]<>#u` はヘルプに記載のない形（古い書式とみられる）。
- [ ] `msgbox` のパラメータ名が正式名か。`ｱｲｺﾝ=` / `ﾎﾞﾀﾝ=` は記載なし。正式名は `アイコン=` / `ボタン指定=`。
- [ ] `メソッド呼出し` と `メソッド呼び出し` が混ざっていないか。ヘルプの表記は後者。
- [ ] `終了 表 #IS表` のように関数で表番号を渡していないか。ヘルプには「定数か変数」か `編集対象表` しか載っていない。
- [ ] 同じ `変数宣言` の `{ }` 内で、同じ名前を2回宣言していないか（例：`{&表名1,&表名1,&表名2}`）。
- [ ] `表` コマンドに `変数使用=` を付けていないか（このパラメータは `結合` にしかない）。
- [ ] イベント（kex）特有の制限を守っているか。
  - `ライブラリ` はメイン処理でのみ。
  - `終了`（一括処理の終了）はイベントでは使えない。
  - `ウィンドウ終了` で自分自身のフォームは閉じられない。
  - `ウィンドウリスト取得` は [フォーム開始] ハンドラ内では結果が不定。
  - `表 …, 使用フォーム=` はハンドラ内では指定できない。
- [ ] 一括処理（cmx）から `オブジェクト操作` / `メソッド呼び出し` を使うとき、`ハンドル=` を指定しているか。
- [ ] `エラー処理 <名札>` を手続きの中で使っていないか（手続き内では `手続き名=` を使う）。
- [ ] `コマンド "…"` の文字列の中に、制御構造（繰り返し・if・ケース・名札など）が入っていないか。

## B. 実行時エラーで止まる可能性（終了状態）

`終了状態=` を指定しないと、失敗したときに一括処理がエラーで止まる。
共有モードで開いた表や、ほかの人も使うファイルが相手のときは特に注意する。

- [ ] 共有更新の表に対する `行訂正` / `行追加` / `行削除` / `置換`：他の人の行ロック（-3）やファイル排他（-2）で止まる。
- [ ] `ファイル削除`：削除に失敗すると止まる。ただし、ループの中で終了状態だけを付けると、同じファイルを探し続けて**無限ループ**になることがある。失敗したら抜ける処理も一緒に入れる。
- [ ] `印字開始`：出力先のフォルダが無いと止まる。
- [ ] `表` / `結合`：`リトライ=しない` にするなら、終了状態は必須。

## C. ロジック

- [ ] 表をまとめて開閉するヘルパー（表名リストと件数を受け取る自作の手続きなど）を使っている場合、**閉じる件数**がリスト内の表の数と合っているか。
  - 例：リストに7表あるのに、閉じる件数に `5` を渡している → 2表が開いたまま残る。
- [ ] 「0 = 全部」のような**特別な値**が、エラー処理の中で偶然渡されていないか。
  - 例：「先頭から n 表を閉じる（0 なら全部）」手続きに、失敗時の後始末で `&i - 1` を渡している。1表目で失敗すると 0 になり、呼び出し前から開いていた表まで閉じてしまう。
- [ ] 回数制限のあるリトライで、到達しない分岐はないか。
  - 例：リトライ回数が5回なのに、`&i = 10` を条件にした分岐がある。同じ条件の `else if` が2つ並んでいれば、2つ目には到達しない。
- [ ] 配列の添字が0や範囲外にならないか。
  - 例：初期値0の変数を添字に使い、ボタン操作の前に参照される経路がある。
- [ ] 呼び出している手続きは定義されているか。このファイルと、`ライブラリ` で読み込むファイルの両方を確認する。見つからなければ「このファイル群では未定義」と書く（ほかのライブラリにある可能性もあるため）。
- [ ] 未宣言の変数を使っていないか。共通変数は、メインメニューなど別のファイルで宣言していることが多い。手元のファイルで確認できなければ「確認できない範囲」に入れる。
- [ ] 型の合わない代入（長整数型に `""` を代入する など）がないか。
- [ ] `繰り返し` / `if` / `ケース開始` と、それを閉じる行の対応が合っているか。`for … End`、`if … end` の別名表記にも注意する。

## D. 注意して扱うこと

- これらのファイルは本番で動いていることが多い。「ヘルプに記載がない」と「誤り」は区別して書く。古い書式でも、桐が受け付けて動いている可能性がある。
- `*` で始まる行や `/* */` の中は注釈なので、検証の対象外。ただし、注釈で無効にしたコードが重要な処理（チェック処理など）を止めている場合は、ひと言触れる。
- 関数（`#曜日`、`#対応文字列` など）は、コマンドとは別のヘルプにある。疑わしいものだけ fnc の目次から調べる。調べなかった場合は「確認していない範囲」に書く。
